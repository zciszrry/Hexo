majorserver / module / task — 任务模块详解

Task 模块是 majorserver 中负责游戏任务（Quest）系统的核心业务模块。它管理了主线任务、日常任务、章节任务、公会任务等多种任务类型的接取、进度追踪、完成判定和奖励发放。

3. 任务模块分类

模块常量 值 名称 说明
TASK_MOD_MAIN 1 主线任务 线性链式推进，完成前置任务后自动接取后续任务
TASK_MOD_DAILY 2 日常任务 每日重置，完成后获得积分可领取宝箱奖励
TASK_MOD_CHAPTER 3 章节任务 按章节分组，一章内所有任务完成后可领取章节大奖并解锁下一章
TASK_MOD_SPECIAL 4 特殊事件任务 已废弃（Deprecated），代码中保留但不再使用

此外还有公会任务（GuildTask），以公会维度进行积分统计，按周重置。

5.2 任务状态流转

6. 事件驱动机制

文件：majorserver/module/task/task_def.go & taskimpl/task_events.go

6.1 事件-任务类型映射（TaskEvent）

task_def.go 中定义了 TaskEvent map[int32][]int32，将游戏事件ID映射到可能受影响的任务类型列表。例如： 

event.EventBuildComplete:  {TaskType_10031, TaskType_20031, TaskType_10233, TaskType_10008, TaskType_10000, TaskType_10311}
event.EventHeroRecruited:  {TaskType_10063, TaskType_20063, TaskType_10401, TaskType_20401}
event.EventSLGKillSoldiers:{TaskType_10377, TaskType_20377}

当游戏中发生某个事件时，系统查表获知哪些任务类型可能受影响，然后对相关任务逐一检查进度。

6.2 事件监听注册

func init() {
    logicfw.AddEventListener(event.AllEvent, onGuildStart)
    logicfw.AddEventListener(event.AllEvent, onEventTask)
}

注册了两个全局事件监听器：

  • onGuildStart：检测章节任务解锁条件，首次满足时初始化第一章任务
  • onEventTask：核心任务进度推进入口，接收所有事件并驱动任务处理

6.3 事件处理流程（onEventTask）

事件派发 (DispatchEvent) │ ▼ onEventTask(event) │ ├── 查询 TaskEvent[event.EventId] 获取相关任务类型列表 │ ├── 从 TaskTypeFuncMap 中获取对应处理函数 │ ▼ handleTasks(ctx, handler) │ ├── 1. 处理日常任务 (doDailyTask) ├── 2. 处理章节任务 (doChapterTask) └── 3. 处理主线任务 (doMainTask) │ └── 若有主线任务完成 → acceptMainTask() 接取后续任务

7. 任务类型处理函数

文件：taskimpl/task_type_func.go & task_process_newtask.go

7.1 函数签名

type FUNCPARAM func(
    r task.AbstractTask,           // 任务数据对象
    aTaskParam conftable.IntArr1,  // 策划配置的参数数组
    ctx *majorserver.TContext,     // 上下文
    aEventId int32,                // 事件ID（0表示接取时调用）
    aEventData []interface{},      // 事件附带数据
    aTaskMod int32,                // 所属任务模块(1/2/3)
    aUid uint64,                   // 玩家UID
) (uint64, uint64)                 // 返回值：(当前进度, 目标值)

7.2 累计型 vs 周期型

类型前缀 含义 接取时(eventId=0)行为 示例
1xxxx 累计型（创建角色后全程计数） 从 CumulativeData 读取历史累计值 10031：累计完成x次城建
2xxxx 周期型（接取任务后开始计数） 初始化进度为 0 20031：完成x次城建
3xxxx 开始型（接取任务后，事件开始时计数） 初始化进度为 0 30031：开始x次建筑升级

7.3 TaskTypeFuncMap 注册表

TaskTypeFuncMap 是一个 map[int32]FUNCPARAM，存储了所有任务类型的处理函数。 当事件触发时，系统通过任务类型ID查找对应函数并调用，实现进度更新。

设计要点：任务类型函数同时承担两种调用场景—— 当 aEventId == 0 时表示"接取任务时的初始化检查"，通常读取累计数据填充初始进度； 当 aEventId > 0 时表示"事件触发的增量更新"，对进度进行增量操作。

8. 主线任务流程

8.1 初始化

玩家创建角色时调用 initMainTaskData → initMainTaskDataLogic：

  • 遍历所有主线任务配置，接取无前置条件的任务（NeedStandTask == 0）
  • 对每个新任务调用类型函数检查是否已满足完成条件
  • 满足条件的直接标记为 Finished，否则标记为 Running
  • 循环处理：已完成的任务可能解锁后续前置任务，继续接取并检查

8.2 事件驱动进度推进（doMainTask）

  • 遍历所有 Running 状态的主线任务
  • 对每个任务根据类型查找处理函数，传入事件数据更新进度
  • 进度达标的任务标记为 Finished，并通过 push.TaskMainChangeNotify 通知客户端

8.3 领奖与后续接取（acceptMainTask）

  • 领奖时一次性领取所有 Finished 的主线任务奖励
  • 将任务状态从 Finished 推进到 Completed
  • 检查已完成任务是否是其他任务的前置，若是则自动接取后续任务
  • 后续任务接取后同样立即检查是否可完成（链式推进）

9. 日常任务流程

9.1 每日重置（resetDailyTasks）

  • 通过比较 lastResetTime 与当前时间判断是否跨天
  • 跨天则清空所有任务数据，重新从配置中接取全部日常任务
  • 同步重置 CompletedTaskData 中的日常任务完成记录

9.2 积分系统

  • 完成日常任务后领取奖励时，同步获得积分（存储在 User 模块的 ERTask 资源中）
  • 积分达到阈值后可领取积分宝箱（DailyTaskBox）
  • 积分同时贡献给公会活跃度（GuildTask.IncreaseScore）

9.3 一键领取（TakeDailyAllTaskAward）

一次性领取所有已完成的日常任务奖励 + 满足条件的积分宝箱奖励。

10. 章节任务流程

10.1 解锁与接取

  • 通过 onGuildStart 事件监听器检测开放条件（GateOfChapterTask）
  • 条件满足后初始化第一章任务（acceptChapterTaskNew）
  • 支持 A/B 测试分组（TaskAB 字段），不同分组的玩家看到不同任务

10.2 进度推进（doChapterTask）

  • 遍历当前 Running 章节中所有子任务
  • 过滤掉已完成/已领奖的任务，仅处理进行中的
  • 进度达标的子任务标记为 Finished

10.3 领奖与章节推进

  • TakeChapterTaskAward：领取单个章节子任务奖励，状态从 Finished → Completed
  • TakeChapterAward：领取整章大奖 + 自动领取未领的子任务奖励
  • 章节完成后自动接取下一章任务（acceptChapterTaskNew(chapterId+1)）

11. 公会任务

  • 以公会（Guild）为单位统计成员活跃积分
  • 成员完成日常任务领奖时，增量累加到 GuildTaskData.Members
  • 按周重置，重置时间通过 NextResetTime 控制
  • FetchGuildTasks 返回成员积分排名和倒计时

12. 累计计数系统（ICumulativeData）

CumulativeData 是独立于任务状态的全局计数器，记录玩家自创建角色以来的各类行为次数。 累计型任务（1xxxx前缀）在接取时从此数据中读取初始进度。

16. 并发与数据安全

所有 RPC 接口和事件处理函数在操作数据前都会调用：

context.LockUserData(uid)    // 用户维度加锁
context.LockGuildData(gid)   // 公会维度加锁（涉及公会数据时）

确保同一用户/公会的数据在并发请求下不会产生竞态条件。数据初始化采用 "Insert失败则重新Get" 的策略处理并发创建场景。

18. 关键设计总结

设计点实现方式
事件驱动 全局事件总线 + TaskEvent映射表 + TaskTypeFuncMap 函数分发
任务链式推进 主线任务通过 NeedStandTask 形成 DAG，完成后自动接取后续
累计/周期双模式 1xxxx从CumulativeData读历史值，2xxxx/3xxxx从0计数
进度实时推送 进度变化时通过 SendMsg 推送 ChangeNotify 给客户端
跨天重置 日常任务在 Fetch 时检测跨天，懒加载式重置
配置热更友好 任务接取和检查逻辑均动态查配置表，不硬编码ID
AB测试支持 章节任务通过 TaskAB 字段区分玩家分组
功能开放联动 章节任务完成后触发 doOpenFunction 解锁游戏功能
注意事项：
1. SpecialTask（特殊事件任务，MOD=4）已被标记为 Deprecated，代码中保留了接口但实现为空。
2. task_cron.go 中的定时任务（每日积分转移、每周公会重置）已全部注释停用，公会重置改为在 FetchGuildTasks 中懒检查。
3. 主线任务的 FirstFlag 用于处理解锁第二章节后首次刷新主线计数的场景。
