SLG 地图系统全景详解

基于代码如实总结 · 八层分层架构 · 自底向上展开
1
空间划分（Spatial Partition）
地图最底层坐标系统，提供高效的区域查询与并发控制能力
单元尺寸说明核心操作
Grid 1×1（最小单位） 地图最小坐标单元，默认整张地图为 512×512 Grid，边长 GRID_LENGTH=100（用于距离计算） CalcGrid(x,y) / ParseGrid(id)
Block 8×8 Grid 默认整张地图包含 64×64 Block；是并发锁的最小粒度（按 BlockId 排序加锁） GetBlockByGrid(grid)
Zone 逻辑分组 策划配置的区域，包含一组 Grid/Block，用于刷怪、刷矿、出生点分配等业务逻辑 配置驱动加载
并发设计：World Service 对对象增删改时，以对象占据的所有 Block 为粒度进行排序加锁（lockBlocks），避免死锁同时保证多对象操作安全。
2
地图对象（静态实体）
放置于 Grid 上的静态实体，统一实现 world.IObj 接口
UserCity Monster Resource SystemCity GuildBuilding Tent Tomb IntelTreasure
所有对象通过 world.IObj 统一描述：
  • GetCenterGrid() / GetOccupyGrids()：占据的格子
  • GetObjectType() / GetTid()：类型与模板ID
  • GetObjWidth() / GetObjHeight()：尺寸（支持多格占据）
  • Same(other)：对象一致性校验
格子特性：Grid 分为 EGridTypeNormal（可放任意对象）、EGridTypeSpecific（仅特定类型）、EGridTypeUnavailable（不可放置）。对象创建前需先 ReserveGrids 预占格子并获取 ticket，创建时凭 ticket 校验。
3
动态实体
地图上具有时间轴与状态机的移动/战斗实体
实体状态机核心字段业务说明
March
行军
  • Clustering（集结中）
  • Clustered（集结到达）
  • Marching（行军中）
  • Arrived（行军到达）
  • Homing（返程中）
  • Homed（返程到达）
 MarchId, MarchOwnerId, ClusterId, TargetGrid, MarchPath 单支部队的行军逻辑；支持转向（改变目标后重新计算路径）；GetNowGrid() 根据时间插值计算当前所在格子
Cluster
集结
  • Waiting（等待加入）
  • WaitAllArrived（等待到达）
  • Marching（集结行军中）
  • Arrived（集结到达）
  • Dismissed（解散）
 ClusterId, ClusterGrid, TargetGrid, WaitBeg/EndTime, Members 多支部队汇聚后统一行军；Members 记录参与的 MarchId
Wander
游荡Boss
  • Wandering（游荡中）
  • Attacking（反击中）
  • Aimed（被集结中）
 WanderId, BirthGrid, TargetGrid, TargetUid, MovePath, LeftHeroArmys 具备 AI 的主动移动实体：游荡 → 发现玩家 → 反击 → 被集结锁定；含过期 Timer 与中断反击 Timer
4
sceneId（地图世界实例标识）
一个进程可托管多个独立地图世界，每个世界拥有独立的 DB 与运行时
  • sceneId 是地图世界的唯一身份证，所有地图操作均通过 ctx.GetSceneId() 路由到对应的实例。
  • 非 SLG 大地图场景（如活动副本）也可复用本框架，通过场景类型减少事件/任务队列资源消耗。
  • 起服时通过 SetLoadFunc 注册各场景的数据加载器：LoadObjFunc / LoadMarchFunc / LoadClusterFunc / LoadWanderFunc / LoadBlockFunc / LoadZoneFunc。
5
slgmap（框架层引擎）
slgmap.SlgMap 是底层地图引擎，采用子服务化架构，提供 11 个核心子模块

子模块职责
world地图对象增删改查、格子预占/释放、Block/Zone 统计、空位搜索（支持强制间隔 forceGap）
march行军/集结/游荡的增删改；加载时从外部 LoadMarchFunc / LoadClusterFunc / LoadWanderFunc 注入
aoi管理每个玩家的 静态 Block 列表 + 动态 Block LRU；维护 block → {uid → viewLevel} 映射
cache框架级通用缓存容器，支持按名称注册 VersionCache，提供命中率统计
push异步消息推送，支持合并推送（PushMsgMerge）按 (sid, uid, method) 去重，定时 flush
event事件总线，多队列缓冲，支持 TriggerWithCtx 触发业务事件（如对象变更、行军状态变化）
timer时间轮定时器（默认 100ms 槽位），用于行军超时、游荡过期等
job异步任务队列，用于推送、RPC 等耗时操作隔离主逻辑
crontab周期性任务（如推送 flush、Watcher 清理）
land领地相关计算，如连通性、领地归属
user_guild玩家与军团信息的外部缓存，带容量与过期时间
6
框架缓存层（快照缓存）
cache.Service 提供的通用数据快照缓存，按视野分级管理 Block 数据
  • 对象数据缓存（CacheNameObjData）：以 objGridId 为 key 缓存对象完整数据。
  • 行军数据缓存（CacheNameMarchData）：以 marchId 为 key 缓存行军/集结/游荡的兵线数据。
  • Block 数据缓存（按视野分级 V1/V2/V3...）：以 blockId 为 key，缓存该 Block 内某视野等级下可见的所有对象/兵线摘要。
缓存失效机制：Commiter 在对象/行军/集结/游荡提交变更后，主动 RemoveKeys 清理受影响的缓存；下次客户端请求时重新组装并写入缓存。缓存带版本号（VersionCache），支持增量比对。
7
业务缓存层（MapCache）
mapcache.TMapCacheMgr 维护业务关系映射，加速业务查询
缓存类型实现典型用途
One2ManyCache[O, M] 双向映射：One→{Many} + Many→One 玩家 UID → 主城 GridId；怪物 Tid → 所有该怪所在的 Grid 列表
Many2ManyCache 双向映射：Parent→{Children} + Child→{Parents} 复杂多对多业务关系（如军团与建筑、活动与格子等）
预热机制：起服时 TMapCacheMgr.Start() 遍历 gNewCacheFuncMap 注册的所有缓存类型并初始化；部分缓存会根据预加载的对象数据主动预热。
8
tSlgMapInsMgr（总管理器）
一进程管多 scene，每个 scene 挂载 4 大组件

地图引擎"] Mgr --> Watch["WatchMgr
关注推送管理"] Mgr --> Rev["RevisionMgr

组件核心实现职责
slgmap.SlgMap sceneId2slgMapIns 底层引擎实例，包含全部 11 个子服务；负责对象/行军/游荡的真实增删改
WatchMgr
TMapWatchManager		 sceneId2slgWatchMgrIns 管理 3 类关注数据：SelfData、GuildWarData、UserAlarmData；维护 uid→dataKeys 与 dataKey→uids 双向映射；支持定时清理离线Watcher、异步通知数据版本更新
RevisionMgr
TBlockRevisionMgr		 sceneId2slgRevisionMgrIns 每个 Block 维护一个 TBlockRevision，记录最近最多 500 条、最长 1小时 的增量修订（对象/兵线的增删改）；支持客户端按版本号拉取增量更新
MapCacheMgr
TMapCacheMgr		 sceneId2slgMapCacheMgrIns 统一管理所有业务缓存（One2Many / Many2Many），按 CacheType 索引
C
Commiter 机制（数据同步桥梁）
对象/行军/集结/游荡在业务层修改后，通过 Commiter 统一提交到框架层
Commiter触发时机核心动作
ObjectCommiter 对象 doAfterUpdate
  • 判断 Create / Destroy / Update，调用 slgmap.World().Add/Del/UpdateObj
  • 清理 CacheNameObjData 及对应视野等级 Block 缓存
  • 向 RevisionMgr 添加 Block 修订记录
  • 通知 WatchMgr 更新数据版本，触发 SelfData / GuildWarData 推送
  • 触发 EUserEventObjectDataChanged 事件
MarchCommiter 行军 doAfterUpdate
  • 调用 slgmap.March().Add/Del/UpdateMarch
  • 清理行军缓存与受影响 Block 的兵线缓存
  • 按 before/after Block 集合计算增删改修订记录
  • 通知行军发起者、目标内部玩家、GuildWar 关注者
ClusterCommiter 集结 doAfterUpdate 类似 MarchCommiter，处理集结整体状态与成员变化
WanderCommiter 游荡 doAfterUpdate 同步游荡状态到 slgmap.March()（游荡在引擎层也作为特殊行军处理），清理缓存并触发修订与推送
设计要点：Commiter 在 Commit() 时对比 initWorldObj 与当前对象状态，仅在实际变化时执行下游同步；所有推送操作通过 ctx.AddSuccDeferCall 延迟到事务成功后执行，保证一致性。

核心关系链

sceneId 是地图世界的身份证 → slgmap.SlgMap 是底层引擎（含 world/march/aoi/cache/push/event/timer/job/crontab/land/user_guild 11 个子服务） → tSlgMapInsMgr 是总控（一进程管理多 scene，每个 scene 挂载 SlgMap + WatchMgr + RevisionMgr + MapCacheMgr 四个组件） → Commiter 是业务层与框架层之间的同步桥梁（负责对象/行军/集结/游荡修改后的统一提交、缓存失效、版本更新、事件触发与客户端推送）。

缓存分两层：框架层缓存（cache.Service）保存数据快照（对象数据 / 行军数据 / Block 分级视野数据），按 key 失效；业务层缓存（mapcache）保存 One2Many / Many2Many 关系映射（如 UID→主城、Tid→怪物格子列表），起服预热。
