majorserver / pointeventtrigger 模块详解

定位：跨活动通用积分/任务进度触发器。监听游戏内玩家行为事件，按活动配置转化为积分并推送给客户端。

1. 模块结构

pointeventtrigger/
├── ipointeventtrigger.go              // 对外接口定义（IPointEventTrigger / IHandler / IExecutor / IData）
├── pointeventtrigger_def.go           // TaskType 枚举 + IOC 单例入口
├── point_event_trigger_ioc.go         // TPointEventTrigger：Handler 注册与事件分派
├── point_event_trigger_defercall.go   // Succ/Fail DeferCall 实现（支持 Merge 累加）
└── pointeventtriggerimpl/
    ├── point_event_trigger_func_def.go    // TaskType→Func 映射 + EventId→TaskType 映射
    ├── point_event_trigger_logic.go       // 24 种任务类型的积分计算逻辑
    ├── point_event_trigger_obj.go         // TPointEventTriggerObj：玩家数据对象
    ├── pointeventtrigger_rpc.go           // RPC：GetInterestActScore
    └── point_event_trigger_in.go          // InModule：FindPointEventTrigger / AddPushScore

2. 核心架构与数据流

整个模块采用 事件监听 → 任务映射 → 活动分派 → DeferCall 合并 → 积分落地 的流水线：

  1. 事件监听：achievementListener 注册到 logicfw 全局事件总线，监听建筑完成、科研完成、训练完成、杀怪、使用道具等事件。
  2. 任务映射：通过 EventIdToTaskType 将一个游戏事件映射到 1~N 个 TaskType（如 EventBuildComplete 同时触发 BuildingBuildOrUpgrade 和 BuildingBuildOrUpgradeLv）。
  3. Handler 遍历：通过 IOC 单例 GetPointEventTriggerIoc().GetHandlersMap() 遍历当前已注册的所有活动 Handler。
  4. 任务筛选：调用 executor.GetRunningPhaseTaskIdByType(ctx, uid, types) 获取该活动当前阶段中，对应类型的任务 ID 列表。
  5. 配置读取：通过 executor.GetParamAndScoreByKey(ctx, taskId) 读取策划配置参数 confParam 与单次积分 score。
  6. 进度计算：大多数任务采用 “累计余数 + 阈值取整” 模式： 
    process = (旧进度 + 本次数值) % threshold
获得积分 = (旧进度 + 本次数值) / threshold * score
新进度 = process  // 保存到 DB
  7. DeferCall 封装：调用 OnIocActive 将结果封装为 TPointEventTriggerDeferCallSucc 与 TPointEventTriggerDeferCallFail 加入上下文。同一帧内相同 executor 的多次调用会自动 Merge 累加 paramsMap。
  8. 积分落地：事务成功后，DeferCall 执行 executor.OnIocActive，将 map[taskId]score 真正写入活动积分系统。
  9. 客户端推送：TPointEventTriggerObj.doAfterUpdate 时通过 push.OnActUserScoreChg 将积分变化推送给玩家。

4. 关键数据结构

4.1 玩家数据对象 TPointEventTriggerObj

每个玩家对应一条 DB 记录，结构为：

TPointEventTrigger
 └── ActivityData[]          // 活动列表
      └── ActivityId
      └── TaskData[]         // 该活动下的任务进度列表
           └── TaskTemplateID
           └── Progress      // 当前任务进度余数

通过 GetProcessByActIdAndTaskId / SetProcessByActIdAndTaskId 读写。首次访问时若 DB 无记录，自动初始化空结构。

4.2 DeferCall 合并机制

TPointEventTriggerDeferCallSucc.Merge 会在同一事务帧内，将相同 executor 的多次调用参数按 key 累加：

for key, value := range source.paramsMap {
    if _, exist := this.paramsMap[key]; exist {
        this.paramsMap[key] += value
    } else {
        this.paramsMap[key] = value
    }
}

这样可以避免玩家一次操作触发大量零散积分写入，减少下游压力。

5. 活动对接方式（多活动并行）

模块通过 IPointEventTriggerHandler 与具体活动解耦：

  • RegisterPointEventTriggerHandler(activityId int32, handler IPointEventTriggerHandler)：活动在开启时注册自己的 Handler。
  • IPointEventTriggerHandler.IsStart()：判断活动是否处于进行状态。
  • IPointEventTriggerHandler.GetExecutor()：返回活动的 Executor，负责读取本活动的任务配置、计算当前阶段任务 ID、校验条件。

因此，同一个游戏行为事件可以同时向多个活动贡献积分。例如一次建筑升级，可能同时计入“联盟决斗”、“军备竞赛”、“七日活动”等多个活动的任务进度。

7. 要点总结

  • 通用化设计：通过 TaskType + EventId 映射 + Handler/Executor 抽象，实现了一套代码支撑多个活动并行计分。
  • 进度余数保存：几乎所有任务类型都保存 Progress 余数，支持策划配置任意阈值（如“每消耗 100 体力得 1 分”），避免数值溢出或精度丢失。
  • DeferCall 合并：利用 logicfw 的延迟调用机制，将一帧内多次操作合并为一次下游写入，提升性能。
  • 条件过滤丰富：支持按建筑类型、士兵等级、道具ID、怪物等级范围、商队品质、敌方军团等维度进行任务匹配。
  • 双保险 Defer：每个调用同时注册 Succ 和 Fail DeferCall，Fail 时仅打印日志不做实际积分变更，确保事务一致性。
