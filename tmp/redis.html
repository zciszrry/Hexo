项目中 Redis 与 Etcd 使用总结

一、Redis 使用总结

1. 使用目的

  • 缓存服务器开服时间：如 _server_open_time_<serverId>，供各服务读取开服时间计算活动周期。
  • 跨服聊天消息缓存：存储跨服频道的聊天记录，实现多服共享聊天数据。
  • 敏感词存储：全局敏感词列表统一存于 Redis，各服务启动时加载。
  • 分布式锁：分组、竞态场景中通过 Redis 锁保证并发安全。
  • 分组数据：跨服分组系统使用 Redis 做数据持久化和锁竞争。

2. 依赖框架

框架/库说明使用位置
gitlab.babeltime.com/serverfw/rediswrapper 公司内部封装的 Redis 客户端，提供连接池、Get/Set、TryLock/Unlock 等 API common/redis, common/mask_words, common/module/chat_base, crossserver/module/armsrace 等
github.com/redis/go-redis/v9 官方 Go Redis 客户端，直接使用 redis.NewClient imserver/module/public/rediscache

3. 连接获取方式

Redis 的连接地址不硬编码，统一从 Etcd 中读取：

// 1. 构造 Redis 在 etcd 中的名字
redisName := util.GetRedisNameByDomain(domain)   // 返回 "domain_<domain>"

// 2. 从 etcd 读取 Redis URL
redisUrl, err := util.GetRedisUrlFromEtcdWithEnv(gameName, redisName)

// 3. 初始化 Redis 客户端（方式一：公司封装）
redisWrapper, err := rediswrapper.NewRedisWrapper(redisUrl)
// 或复用全局实例
redisWrapper, err := rediswrapper.GetOrInitGlobalRedisWrapper(redisUrl)

// 4. 初始化 Redis 客户端（方式二：官方库，imserver 中使用）
opt, _ := redis.ParseURL(redisUrl)
rdb := redis.NewClient(opt)

4. 核心使用方法

操作示例代码说明
Get val, exist, err := redisWrapper.Get(key) 读取字符串值，exist 表示 key 是否存在
Set err := redisWrapper.Set(key, value, 0) 写入字符串值，第三个参数为过期时间（0 表示永不过期）
TryLock isLock, err := redisWrapper.TryLock(lockKey, timeout) 尝试获取分布式锁，返回是否加锁成功
Unlock err := redisWrapper.Unlock(lockKey) 释放分布式锁

5. 典型使用场景示例

跨服聊天缓存（common/module/chat_base/chat_cross_redis.go）：

// 将聊天消息 JSON 序列化后写入 Redis
data, _ := json.Marshal(chatMsgCache)
redisHandler.Set(redisKey, data, 0)

// 从 Redis 读取并反序列化
cacheStr, exist, err := redisHandler.Get(redisKey)
json.Unmarshal([]byte(cacheStr), &chatMsgCache)

分布式锁在分组中的使用（crossserver/module/group/groupimpl/group_logic.go）：

err := grouping.DoTeamGrouping(...)
if errors.Is(err, rediswrapper.ErrAlreadyOwned) {
    // 未拿到锁，等待重试
    time.Sleep(...)
}

二、Etcd 使用总结

1. 使用目的

  • 配置中心：集中存储游戏全局动态配置（版本号、防火墙开关、封号规则、活动开关等），支持热更新。
  • 服务配置发现：Redis、MySQL 等中间件的连接地址统一注册到 Etcd，服务启动时动态拉取。
  • 配置监听（Watch）：监听指定 key 的变化，实现配置变更的实时生效，无需重启服务。

2. 依赖框架

框架/库说明使用位置
gitlab.babeltime.com/serverfw/etcdwrapper 底层 Etcd 封装，提供 Init / GetEtcdClient / Get / Set / Watch 等基础 API common/util, common/mask_words, 各 server 启动入口
gitlab.babeltime.com/serverfw/etcdwrapper/etcdutil 高级封装 TGlobalSettingsBase，提供批量初始化、全量监听、回调更新等能力 common/globalsettings

3. 初始化与连接

// 在各服务启动入口（如 majorserver/bin/majorserver.go, imserver/bin/imcore.go 等）
err := etcdwrapper.Init(config.EtcdEndPoints, config.GN)
// EtcdEndPoints 示例：[]string{"192.168.x.x:2379", ...}
// GN 为游戏项目名，如 "cs3"

4. 核心使用方法

操作API说明
获取客户端 cli, err := etcdwrapper.GetEtcdClient() 获取全局 Etcd 客户端实例
读取 Key kvs, err := cli.Get(path) 返回 key-value 列表
写入 Key cli.Set(path, value)（封装内） 向 Etcd 写入配置值
监听变化 watchChan := cli.Watch(key) 阻塞监听 key 的 Create / Modify / Delete 事件
批量监听配置 globalSettingsBase.InitAndWatch(gn, domain, handler) 初始化并监听 <gn>/<domain>/settings/ 下所有配置

5. Etcd 路径约定

用途路径格式示例
Redis 地址配置 <gn>/redis/<redisName> cs3/redis/domain_mhf
DB 地址配置 <gn>/db/<dbName> cs3/db/cs3_majorserver_s1
全局状态配置 <gn>/<domain>/settings/status/... .../status/version_update_time
全局控制配置 <gn>/<domain>/settings/control/... .../control/firewall_is_on

6. 典型使用场景示例

从 Etcd 读取 Redis 地址（common/util/etcd_client_util.go）：

func getValueFromEtcd(aPath string) (string, error) {
    etcdcli, err := etcdwrapper.GetEtcdClient()
    kvs, err := etcdcli.Get(aPath)
    if len(kvs) > 0 {
        return string(kvs[0].Value), nil
    }
    return "", fmt.Errorf("not found path:%s", aPath)
}

敏感词更新监听（common/mask_words/mask_words_mgr.go）：

func watchMaskWordsUpdateTime() {
    watchChan := gMgr.etcdClient.Watch(gMgr.etcdKey)
    for info := range watchChan {
        for _, event := range info.Events {
            if event.IsCreate() || event.IsModify() {
                // 配置变更，重新从 Redis 加载敏感词
                handlerMaskWordsUpdate(string(event.Kv.Key), string(event.Kv.Value))
            }
        }
    }
}

全局配置热更新（common/globalsettings/globalsettings.go）：

// 初始化并监听所有 settings 节点
globalSettings.GetGlobalSettings().InitAndWatch(config.GN, config.Domain)

// 内部通过 etcdutil.TGlobalSettingsBase 监听 /settings/ 前缀
// 当任意配置变更时，回调 SetKeyValue(aKey, aValue) 更新内存

四、总结

  • Etcd 在本项目中承担配置中心与服务注册发现的角色，所有服务的 Redis、DB 地址以及大量运行时开关都存放于此；通过 Watch 机制实现配置热更新。
  • Redis 主要作为高速缓存和分布式锁的载体，支撑跨服聊天、敏感词、开服时间、分组竞争等场景。
  • 两者通过 GetRedisUrlFromEtcdWithEnv 串联：服务启动时先从 Etcd 拿到 Redis 地址，再初始化 Redis 客户端。
