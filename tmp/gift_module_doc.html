majorserver / module / gift — 礼物系统详解

Gift 模块是 majorserver 中的社交礼物系统（非礼包/商城系统），负责玩家之间赠送礼物、礼物展台展示、赠礼记录管理、礼物经验等级等功能。该系统增强了游戏的社交互动体验。

重要区分：此模块是"礼物系统"（玩家间社交赠礼），而非"礼包系统"（商城道具包）。礼包系统位于 module/gift 同级的其他模块中。

3. 核心概念

3.1 礼物（Gift Item）

礼物是可以在玩家之间赠送的虚拟物品。每种礼物有唯一的 GiftTid（配置表ID），具有类型（免费/付费）、批次数量、经验值、花费等属性。

3.2 礼物经验与等级

玩家每次赠送礼物会获得经验值（ERGiftExp 资源类型）。经验累计到一定值后提升礼物等级，每个等级可以领取对应的等级奖励。

3.3 展台系统（Showcase）

每个玩家拥有一个"礼物展台"，可以将收到的礼物放入展台栏位进行展示。其他玩家访问时可以看到展台上的礼物及其数量、赠送者信息等。展台栏位数量由配置 ShowMax 控制。

3.4 赠礼记录（Record）

每次赠礼都会产生一条记录，包含发送者UID、礼物类型、数量、时间、自定义留言、是否匿名等信息。记录有最大保存数量和有效期限制。

3.5 累计最大赠送者（MaxFromUid）

系统追踪每种礼物中"累计赠送数量最多"的玩家。该计算通过异步延迟任务完成，避免阻塞主流程。

8. 展台系统

8.1 数据结构

展台数据以 protobuf (TGiftShowcaseInfo) 序列化后存储为字节数组。每个展示项包含：礼物TID、累计收到数量、当前展示批次数量、展示位索引。

8.2 修改展台（ModifyShowcase）

  • 客户端传入礼物TID数组，数组索引即为展台位置
  • 校验数组长度不超过 ShowMax
  • 校验不存在重复TID（同一礼物不能占多个位置）
  • 更新各礼物的 ShowIdx 字段
  • 重新序列化展台字节数据

8.3 修改礼物展示设定（ModifyGiftShow）

每个礼物的展示可以独立配置：

设定项说明
IsShowMax是否对外展示"累计赠送最多的玩家"
IsShowMsg是否对外展示"自定义留言"
MsgRecordId选择哪条赠礼记录的留言作为展示
ShowNum展示的批次数量（需已解锁）

8.4 展台数据更新时机

以下操作会触发 updateShowcaseBytes()：

  • 修改展台布局（ModifyShowcase）
  • 修改礼物展示设定（ModifyGiftShow，仅当礼物在展台中时）
  • 收到新礼物且该礼物已在展台中
  • 对象初始化时展台数据为空

9. 赠礼记录管理

9.1 记录存储

记录存储在两个层面：

  • 玩家级：TGift.ArrRecord — 存储在玩家数据中，用于客户端展示
  • 服务器级：TServerGiftRecord — 独立数据库表，用于异步任务统计

9.2 记录过期清理（AutoRefresh）

在对象加载时自动执行清理：

  • 超过 RecordMaxTime（秒）的记录被删除
  • 同种礼物超过 RecordMaxNum 条的旧记录被删除
  • 被礼物展示引用的记录（MsgRecordId）不会被清理

9.3 拉取记录（GetRecordList）

支持按礼物类型筛选（GiftTid），支持游标分页（MinRecordId + Limit），记录按时间倒序返回。匿名赠送的记录不会返回发送者UID。

10. 累计赠送排名（异步任务）

文件：giftimpl/gift_task.go

10.1 触发时机

每次收到礼物后调用 resetTaskUpdateMaxFromUid，注册一个延迟 5 秒的异步任务。短时间内多次赠送只会在最后一次 5 秒后统一计算，避免频繁查库。

10.2 任务执行流程（onTaskUpdateMaxFromUid）

1. 获取玩家当前最大有效记录ID（用于过滤无效数据） │ ▼ 2. 分页查询 TServerGiftRecord 表 WHERE RecvUid=? AND GiftTid=? ORDER BY RecordId ASC │ ▼ 3. 按 SenderUid 聚合累计赠送数量 构建 uid2SortParams map │ ▼ 4. 排序：AccNum 降序, SendTime 升序（相同数量早送者优先） │ ▼ 5. 加锁后更新接收者数据： - 设置 MaxFromUid（排名第1） - 清空并重建 ArrFromAcc（前10名）

10.3 排序规则

sort.Slice(aArr, func(i, j int) bool {
    if aArr[i].AccNum != aArr[j].AccNum {
        return aArr[i].AccNum > aArr[j].AccNum  // 赠送多的在前
    }
    return aArr[i].SendTime < aArr[j].SendTime  // 同数量时早送的在前
})

17.1 初始化

func findGiftData(ctx, uid) IGiftData {
    dbStruct := tables.NewTGift()
    dbStruct.SetUid(uid)

    if err == sql.ErrNoRows {

17.2 AutoRefresh（加载后自动刷新）

  • 清理过期记录（按时间和数量）
  • 初始化展台序列化数据（若为空）
  • 重置变更推送标记

17.3 doAfterUpdate（更新后推送）

对象被修改并提交后，检查 needPushGiftTid 和 needPushRecordIdToSender，若有变化则向客户端发送 push.UpdateGiftDataNotify 推送。

18. 关键设计总结

设计点实现方式
社交赠礼 锁定双方数据，原子操作扣减发送者库存、增加接收者记录
自动购买 付费型礼物库存不足时自动扣费补齐，无缝体验
展台展示 protobuf序列化存储，供其他模块（如个人主页）高效读取
匿名赠送 记录层面存储真实UID，展示层面按 IsUnnamed 过滤
累计排名异步化 通过延迟任务（5秒后）查询服务器级记录表统一计算，避免阻塞主流程
记录过期清理 对象加载时懒清理，被引用的记录豁免
敏感词过滤 自定义留言经过 mask_words 过滤后存储
聊天联动 世界频道/私聊消息，按批次档位自动选择频道
变更推送合并 通过 markPush 标记，在 doAfterUpdate 中一次性推送所有变化
经验同步 监听资源增加事件，ERGiftExp 变化时同步到 Gift 模块
扩展说明：
1. 礼物的拥有数量（OwnNum）可通过其他系统增加（如活动奖励），Gift 模块实现了 ILogicAddNum/SubNum/GetNum 接口供外部模块调用。
2. GmFixShowcase() 提供了GM命令修复展台数据的能力，可在数据异常时使用。
3. 批次展示数量（ShowNum）需要先通过接收对应批次的赠礼来解锁，解锁后才能选择该批次作为展示。
